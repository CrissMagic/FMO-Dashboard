# FMO 中继控制功能说明

本文档说明本分支新增的 FMO 控制相关功能，方便维护者评估和后续调整。

## 新增功能

### 通联卡片呼号跳转 QRZ

在通联详情卡片中，以下呼号会显示为可点击链接：

- 卡片标题呼号
- 接收方呼号
- 发送方呼号
- 中继管理员呼号

点击后会在新页面打开 QRZ 查询页，例如：

```text
https://www.qrz.com/db/BH1KZQ
```

### FMO 中继控制页

“更多”页面中的“远程控制”已调整为“FMO 控制”，页面上方新增 FMO 中继控制区域，原 APRS 远程控制保留在下方。

中继控制区域支持：

- 显示当前中继
- 刷新当前中继
- 切换上一中继
- 切换下一中继
- 打开中继列表并选择中继
- 手动填写控制地址

控制地址默认使用：

```text
ws://192.168.31.146
```

也会优先使用项目设置里已经选择的 FMO 地址。

### 实时仪表盘

顶部主导航新增“仪表盘”页面，用于查看当前 FMO 的实时通联概览。

仪表盘会直接请求 FMO API，不依赖本地 IndexedDB 数据。页面内容包括：

- 顶部显示当前正在使用的中继名称
- 显示控制地址和中继 UID
- 显示最近 20 条通联
- 每条通联显示呼号、时间、留言、模式、中继
- 默认每 5 秒自动刷新一次
- 中继名称支持点击切换到对应中继

该页面适合放在浏览器中常开，用作实时通联观察面板。

### 从通联日志切换中继

通联日志列表中的“中继”列现在可以点击中继名称。点击后会尝试将当前 FMO 设备切换到该中继。

通联详情卡片中的“中继”名称也支持同样的点击切换。

## 实现方式

### 标准 / 待机模式直控

足迹页的“当前连接”卡片，以及“更多 → FMO 控制”中均提供设备模式控件，控制对象为当前显示的 FMO 地址。

- 读取：`{type: 'ui', subType: 'getScreenMode', data: {}}`，响应 `data.mode` 为 `0`（标准）或 `1`（待机）。
- 切换：`{type: 'ui', subType: 'setScreenMode', data: {mode: 0 | 1}}`。检查 API 状态码和 `data.result`，随后轮询读取模式，确认目标模式后才更新界面。
- 对写入超时不自动重发；读取失败或切换未确认时显示“未知”，可手动刷新。状态按协议和主机分别保存，切换设备时不会串用上一台的模式。
- 页面可见时每 15 秒刷新，重新回到窗口时也刷新。卡片的内部滚动行为保留。

协议已对照盒子网页的 `uiService.js` 核实，并通过真实设备只读验证 `getScreenModeResponse`。写入与错误处理通过模拟设备验证，不自动切换真实盒子做测试。实现位于平台层和 Pinia store，`DeviceModeControl.vue` 为共用界面。回归检查：`npm run test:device-control`。

项目中原本已经封装了 FMO WebSocket API，例如：

- `getCurrentStation`
- `getAllStations`
- `setCurrentStation`
- `nextStation`
- `prevStation`

本功能复用了这些接口。

由于目前通联日志中保存的是：

- `relayName`
- `relayAdmin`

没有保存中继 UID，因此从日志切换中继时采用以下流程：

1. 读取 FMO 当前中继列表
2. 使用日志里的 `relayName` 按名称匹配中继
3. 找到匹配项后使用该中继的 `uid` 调用 `setCurrentStation`
4. 等待约 700ms 后重新读取当前中继，更新页面状态

## 已知限制

- 如果中继名称在 FMO 中继列表中不存在，则无法自动切换。
- 如果多个中继名称完全相同，当前实现会使用第一个匹配结果。
- 日志中没有保存中继 UID，因此名称匹配是当前可用的折中方案。
- 切换中继会真实改变 FMO 设备当前连接状态，属于外部可见操作。

## 当前中继公开广播信息

顶部中继旁显示未过期的广播在线人数；“设备信息 → 中继公开广播”显示在线／历史峰值人数、管理员、广播状态、覆盖半径、服务器地址、说明和广播时间。

- 数据来自 FMO APRS 地图（https://map.fmo.net.cn/）使用的公共快照 `https://map.srv.ink/v401/api/bootstrap`，已确认支持浏览器跨域。第三方服务可用性、格式和数据新鲜度不由本项目保证。
- 仅按设备返回的当前中继 UID 匹配 `mode=server`、`identityTrust=verified` 的 `server.nodeId`，选择最新广播；不按同名中继或守听客户端数量推算。
- 页面可见时每分钟检查，快照请求合并并缓存一分钟；返回前台补查。广播通常每十分钟更新，超过二十分钟或时间异常时标为过期，顶部不显示过期人数。失败时说明查询失败，保留同一目标上次广播及时间。
- 缺失人数显示“未提供”，真实的零人数保留为 `0`。切换设备／协议／中继立即清除旧结果，并忽略已过时请求。
- 实机核实：`192.168.1.110` 返回中继 UID `2200`，公共广播可匹配“精品毛血旺（渝）”，浏览器已验证在线 `17`、历史峰值 `81` 的显示（示例为验证时的广播快照）。未修改盒子模式或中继。
- 回归检查：`npm run test:relay-status`，覆盖零值、缺失值、同名不同 UID、非服务器／未验证记录、过期数据、请求缓存、失败重试和设备切换竞态。


### 广播信息显示与可读性整理

- 顶部将广播快照人数和相对更新时间放在一起，点击人数可直接打开设备信息中的中继广播。过期数据显示“上次广播／已过期”，失败时保留上次记录并提示查询失败。
- 广播中继名称、UID、时间、在线／峰值与状态在详情顶部；服务器参数和设备连接诊断可折叠展开。
- 手机完整展示中继名称，切换按钮点击范围为 44px。关键辅助文字至少 12px，等待态标题收敛，上次通联信息加强；800×600 使用紧凑顶栏以保留表格阅读空间。
- 仪表盘上方统计明确为“本地日志”，来源为已同步的本地数据库；下方列表注明“盒子日志与实时发言”。零统计不会再回退混用独立友台数量与通联记录数量。
